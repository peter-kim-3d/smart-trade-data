# collect-1688

## 작업 위치
smart-trade-data repo 루트에서 작업한다. 경로를 모르면 이 SKILL.md의 실제 위치를
realpath로 확인해(심링크 역추적) repo 루트를 찾는다.

## 언제 사용
메시지에 1688 상품 링크(detail.1688.com 또는 m.1688.com의 /offer/{id})나
offer id(9자리 이상 숫자)가 있을 때. 없으면 이 스킬을 시작하지 말고 일반 대화로 답한다.

## 입력 파싱
- 정규식 1688\.com/offer/(\d+) 우선, 없으면 단독 9자리 이상 숫자.
- 한 메시지에 여러 개면 전부 대상, 등장 순서대로.
- 텍스트 파일 첨부(txt/md/csv)는 내용을 읽어 같은 패턴으로 추출. 그 외 형식은 미지원 안내.
- 메시지에 "재수집"이 있으면 해당 id는 force 모드.

## 절차 (id당 순차, id 사이 30초 대기)
1. repo 루트에서 git pull --rebase
2. 중복: products/1688/{id}_* 존재하고 force 아님 → "이미 수집됨: {폴더}" 보고 후 다음 id.
3. force면: 해당 폴더의 01~05 디렉토리와 폴더 README.md만 삭제 후 재수집.
   06_가공/·07_생성/이 존재하면 절대 건드리지 말고, 완료 보고에
   "⚠️ 원본 갱신됨 — 기존 가공/생성물 검토 필요"를 포함한다.
4. bash scripts/1688/collect_auto.sh {id} products/1688
5. 검증 게이트: 폴더 생성 / 05_원본데이터/summary.json 존재 + title 비어있지 않음 /
   메인이미지 ≥1 / SKU_가격표.csv ≥1행 / 동영상 있으면 >0바이트.
   실패 시 playbook/1688-collection.md 트러블슈팅 표를 참고해 1회 재시도.
   그래도 실패면 부분 산출물 삭제(커밋 금지) 후 ❌ 보고하고 다음 id로.
6. LLM 산출물 작성(플레이북 출력 규격): 01_상품정보/상품정보_한국어_번역.md,
   02_상세페이지/상세페이지_설명.md, 폴더 README.md
7. products/1688/INDEX.md에 행 추가/갱신:
   | {id} | {제목 요약} | YYYY-MM-DD |  |  |  |
   수집 열만 채운다. 가공·생성 열은 다른 스킬 소관.
8. git add {폴더} products/1688/INDEX.md && git commit -m "collect(1688): {id} {슬러그}"
   && git push. 실패 시 git pull --rebase 후 1회 재시도.
9. 스레드 보고: 제목(中/韓) · 가격범위 · MOQ · SKU 수 · 이미지 수(메인/상세) ·
   동영상 유무 · 수집 경로(데스크톱/모바일) · 폴더 · 커밋 해시

## 금지 / 보안
- 수집 로직 재작성 금지 — 반드시 scripts/1688/collect_auto.sh 사용.
- 1688에는 GET(읽기)만. 로그인/주문/결제 시도 금지.
  로그인 수집(Phase 2) 요청은 "사람 개입 필요"라고만 안내.
- 쿠키·토큰·개인키를 채팅/로그에 출력 금지.
  채널에 cookies 파일이 올라오면 저장하지 말고 삭제를 요청.
- products/*/06_가공·07_생성은 이 스킬이 절대 수정/삭제하지 않는다.

## 변경 관리
- scripts/·플레이북·이 스킬 수정 시 별도 커밋으로, 커밋 전
  bash scripts/1688/collect_auto.sh 889272226600 /tmp/st-smoke 셀프테스트 통과 필수.
- 반복 실수에서 배운 것은 이 SKILL.md에 추가하고 커밋한다 (tune(collect): …).
- 승인 범위를 벗어나지 않는다. 리뷰 중 원래 승인과 무관한 개선(예: 보안 하드닝)이 나오면
  즉시 멈추고 `BACKLOG.md`에 기록한 뒤 별도 승인을 받는다. 스코프 크리프 금지.
- 독립 리뷰는 최종 diff 기준 최대 1회만 수행한다. 리뷰가 새 결함을 계속 만들어내면 차단 결함
  (실제 데이터 손상·자격증명 유출)만 고치고 나머지는 `BACKLOG.md`로 넘긴다. 무한 리뷰 루프 금지.
- 이 수집 스크립트의 위협 모델은 "신뢰된 컨테이너에서 우리가 직접 실행하는 GET"이다.
  로컬 동시 공격자·TOCTOU·심링크 교체 방어는 이 스코프 밖이며 별도 승인이 필요하다.
- Codex provider는 공격·exploit 코드에 민감해 안전 필터에 막힐 수 있다. 보안 관련 작업은
  방어 관점으로만 서술하고, 차단되면 `hermes fallback`으로 provider를 전환한다.
