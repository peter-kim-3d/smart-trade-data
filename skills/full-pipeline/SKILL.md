# full-pipeline

## 언제 사용
"끝까지"/"풀파이프라인"/"전체처리" + 1688 링크 또는 offer id 일 때.

## 원칙
기존 4개 스킬을 순서대로 호출하는 오케스트레이터다. 각 단계 로직을 새로 만들지 않고
해당 스킬을 그대로 따른다. 각 단계 완료 후 다음으로 넘어간다.
단계가 실패하면 거기서 멈추고 어느 단계에서 왜 실패했는지 보고 (뒷 단계 진행 안 함).

## 절차 (offer id 또는 링크 하나당)
1. [수집] collect-1688 스킬 실행. (이미 수집돼 있으면 skip하고 다음)
2. [텍스트추출] process-images 스킬 실행 → 06_가공/text_extract.json (zh/ko/copy_a/copy_b)
3. [클린] clean-images 스킬 실행 → 06_가공/clean/
4. [카피] apply-copy 스킬 실행 → 06_가공/final_A/, final_B/
5. 각 단계는 그 스킬에 정의된 대로 커밋·push 한다.
6. 전체 완료 후 Slack 종합 보고:
   - 각 단계 성공/실패
   - 최종 산출물 요약 (이미지 수, 텍스트 있는 이미지 수, 쿼터 총소모)
   - 문제 있던 이미지 있으면 목록

## 주의
- 쿼터: clean+copy가 이미지당 여러 번 생성이라 큰 상품은 쿼터를 꽤 쓴다.
  시작 전 codex 사용량 확인, 상품이 크면(이미지 수십 장) 규모를 먼저 알린다.
- 중간 실패 시 이미 끝난 단계는 커밋돼 있으므로, 그 다음 단계만 재실행하면 된다.

## 변경 관리
- 승인 범위 벗어난 개선은 BACKLOG. 독립 리뷰는 최종 diff 1회.
